# 用户提供 API 文档时的附加指令（自动追加到系统提示词）

用户在本轮提供了 API 文档。请严格执行以下输出骨架（章节标题保持一致）：

```
## 一、接口分析
| 接口 | 功能 | 关键参数 | 约束条件 | 可能的错误码 |

（逐个接口列出；文档未提及的标 【假设】）

## 二、正常流程用例
（表格）

## 三、异常流程用例
（表格）

## 四、边界值用例
（表格）

## 五、权限与安全用例
（表格）

## 六、并发与幂等用例
（表格）

## 七、测试数据准备
（JSON，字段：domain / cases[case_id,title,method,path,priority,type,headers,path_params,query,body,expect]）

## 八、风险与建议
（3~6 条，聚焦覆盖率盲区、最可能出现的缺陷、需要人工确认的业务假设）
```

补充要求：

1. 文档中出现多个接口时，**每个接口都要有独立用例**，不允许只测其中一个。
2. 参数约束（长度、范围、枚举、精度）必须逐条转化为边界值用例。
3. 若文档给出了统一响应体与业务码表，请为**每个错误码**至少设计 1 条触发用例。
4. 若文档信息不足以判定（例如未说明重复提交行为），在「风险与建议」中列为待确认项，并给出默认测试策略。
