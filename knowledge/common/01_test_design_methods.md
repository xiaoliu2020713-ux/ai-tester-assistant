# 通用测试设计方法（跨业务域基线）

> 适用：图书管理系统 / 电商平台 / 学生选课系统 以及后续新增的任何业务域。
> 用途：AI 测试员生成测试用例时，必须覆盖以下设计方法，避免只写「正常流程」。

## 1. 等价类划分（Equivalence Partitioning）

对每个输入参数划分有效等价类与无效等价类，每个等价类至少一条用例。

| 参数类型 | 有效等价类示例 | 无效等价类示例 |
| --- | --- | --- |
| 字符串 ID | 存在的合法 ID | 不存在、空串、全空格、超长（> 255）、含 SQL/脚本注入字符 |
| 枚举状态 | 允许的状态值 | 未定义状态、大小写变体、数字代替字符串 |
| 数值（数量/金额） | 区间内的正常值 | 负数、0、超大值、超精度小数（如 0.001 元） |
| 日期时间 | 合法且符合业务窗口 | 非法日期（2025-02-30）、时区错乱、过去/未来越界 |
| 布尔/标志位 | true / false | null、字符串 "true"、1/0 |

## 2. 边界值分析（Boundary Value Analysis）

每个有范围约束的字段，必须覆盖：**下界-1、下界、下界+1、上界-1、上界、上界+1**。

常见边界清单（生成用例时逐条对照）：

- 分页：`page=0`、`page=1`、`page=负数`、`page_size=0`、`page_size=1`、`page_size=最大值`、`page_size=最大值+1`、超出总页数
- 数量：`0`、`1`、`库存/容量恰好等于请求量`、`库存/容量 = 请求量 - 1`、极大值
- 金额：`0.00`、`0.01`、`最小货币单位`、`优惠后为 0`、`优惠后为负`、`超出账户/限额`
- 长度：`空串`、`1 字符`、`最大长度`、`最大长度+1`、`含 emoji / 中文 / 全角`
- 时间：`恰好开始时间`、`开始前 1 秒`、`恰好结束时间`、`结束后 1 秒`、`跨越自然日/学期`
- 并发：`同时最后 1 件库存`、`同一用户重复提交`、`重复回调`

## 3. 判定表与因果图（状态与组合）

多条件组合场景使用判定表，重点覆盖：

- 条件全真、条件全假
- 单条件取反（每次只翻一个条件）
- 互斥条件同时成立时的优先级（例如「已下架商品」同时「有库存」）
- 状态机的非法跃迁（例如订单从「待支付」直接跳到「已完成」）

## 4. 场景法（主流程 + 备选流 + 异常流）

每条业务用例至少包含：

1. **主成功场景（Happy Path）**：前置条件 → 操作 → 期望结果；
2. **备选流**：合法但非主线的分支（如使用优惠券、改期、部分归还）；
3. **异常流**：参数错误、权限不足、资源不存在、依赖服务失败、超时、重复提交。

## 5. 错误推测与风险优先级

优先设计以下高风险用例（发现缺陷概率最高）：

- **幂等性**：重复提交同一请求（同 `requestId` / 幂等键）是否只产生一次业务效果；
- **一致性**：跨表/跨服务数据是否一致（下单扣库存、借书减可借册数、选课减余量）；
- **并发**：超卖、超借、超选、重复扣款、双重优惠；
- **权限**：越权访问他人资源（水平越权）、低权限执行高权限操作（垂直越权）、未登录访问；
- **边界与精度**：金额浮点误差、四舍五入方向、库存回滚；
- **兼容与容错**：`Content-Type` 错误、非法 JSON、字段缺失、超长字段、特殊字符、编码；
- **可观测**：错误码与错误信息是否可区分、是否泄露内部实现细节。

## 6. 用例优先级定义

| 级别 | 含义 | 覆盖范围 |
| --- | --- | --- |
| P0 | 阻断级，核心链路失败即不可用 | 主流程、支付/借还/选课等资金与资源一致性 |
| P1 | 重要，主要功能或高频异常 | 常规异常流、边界值、权限校验 |
| P2 | 一般，影响体验或低频场景 | 非关键校验、提示文案 |
| P3 | 低，优化类 | 性能与易用性建议 |

## 7. 通过标准（Pass/Fail 判定原则）

- 期望结果必须**可观测、可判定**：明确 HTTP 状态码、业务错误码、数据库状态、返回字段值；
- 不接受「返回正确」「提示友好」等模糊描述；
- 涉及时间与并发的用例必须写明**执行方式**（如使用脚本并发 20 个请求）。
