# 接口测试基线检查清单（任何业务域通用）

> 拿到任意一份 API 文档后，AI 测试员应逐条对照本清单生成用例，不要遗漏。

## 1. 请求层（Request）

| 检查项 | 典型用例 | 期望 |
| --- | --- | --- |
| 必填字段缺失 | 逐个删除必填字段 | 400 + 明确业务码，指明缺失字段 |
| 字段类型错误 | 数字传字符串、对象传数组 | 400，不抛 500 |
| 字段超长 | 超过最大长度 1 个字符 | 400 或按文档截断策略 |
| 特殊字符 | `<script>`、SQL 注入串、emoji、全角、`\0` | 正确转义/拒绝，无 500 |
| 空值与 null | `""`、`"   "`、`null`、缺省 | 按文档区分「未传」与「传空」语义 |
| 多余字段 | 传未知字段 | 忽略或 400（与文档一致） |
| 非法 JSON | 缺大括号、尾部逗号 | 400，不抛 500 |
| Content-Type 错误 | `text/plain` 发 JSON | 415 或 400 |
| 超大请求体 | 超过网关限制 | 413 |
| 路径参数非法 | 不存在 ID、非法格式、空 | 404 / 400，语义正确 |
| 分页参数 | page/pageSize 边界与负数 | 空列表或 400，不返回全量 |
| 排序与过滤 | 非法排序字段、注入 | 400 或忽略，无 500 |

## 2. 认证与权限（AuthN / AuthZ）

- 无 Token / 过期 Token / 伪造签名 Token / 其他用户 Token → 401
- 水平越权：用 A 用户 Token 访问 B 用户的资源 ID → 403，且**不得返回数据**
- 垂直越权：普通用户调用管理端接口 → 403
- 角色边界：接口文档声明的每个角色各测一次允许与拒绝
- Token 失效时机：登出后旧 Token 是否立即失效；刷新 Token 是否可用

## 3. 幂等与重复提交

- 相同幂等键重复提交 → 只产生一次副作用，返回结果一致
- 无幂等键的写接口重复提交 → 明确是拒绝还是产生重复数据（与设计一致）
- 支付/扣减类回调重复推送 → 只入账一次

## 4. 并发与一致性

- 最后 1 件库存/最后 1 个名额被 N 个请求同时争抢 → 成功数 = 1，其余明确失败
- 并发修改同一条记录 → 无脏写，或按乐观锁返回冲突（409/业务码）
- 事务回滚：主表写入成功、从表失败时是否整体回滚
- 缓存与 DB 一致性：更新后立即查询是否读到新值

## 5. 响应层（Response）

| 检查项 | 说明 |
| --- | --- |
| 状态码语义 | 200/201/204/400/401/403/404/409/422/429/500 与场景匹配 |
| 响应结构 | 字段齐全、类型正确、无多余敏感字段（密码、内部 ID） |
| 错误码 | 不同失败原因有不同业务码，可区分 |
| 错误信息 | 可用于排查但不泄露堆栈、SQL、内网地址 |
| 分页结构 | total/page/pageSize/items 一致，total 与真实数量吻合 |
| 时间与金额格式 | 时区（建议带时区或 UTC）、金额单位（分/元）统一 |
| 空结果 | 返回 `[]` 而非 `null`，前端不报错 |

## 6. 兼容与运维

- 版本兼容：`/v1` 与 `/v2` 行为差异与文档一致
- 限流：超过 QPS 返回 429，恢复后可继续
- 超时与重试：依赖服务超时是否有兜底，重试是否造成重复副作用
- 可观测：日志中可用 traceId 串联一次请求

## 7. 使用建议

1. 先解析文档中的「接口清单」，为每个接口建一行记录（方法、路径、必填、约束）；
2. 对每个接口套用上面 1~5 的检查项，命中即生成用例；
3. 无法自动判定的项（如「提示友好」）改写为可判定断言或标注为人工验证。
