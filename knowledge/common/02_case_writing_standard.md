# 用例编写规范与结构化输出格式（阶段二可直接解析）

> 本文件定义了 AI 测试员**必须遵守**的输出格式。
> 阶段二的自动化执行模块会直接解析该格式生成 pytest 脚本，因此字段名与顺序不可随意更改。

## 1. 单个测试用例的标准字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `用例ID` | 是 | 格式 `TC-<模块缩写>-<三位序号>`，如 `TC-BOOK-001` |
| `用例标题` | 是 | 一句话说明「在什么条件下做什么，期望什么」 |
| `所属域` | 是 | 图书管理系统 / 电商平台 / 学生选课系统 |
| `接口` | 是 | `METHOD /path`，如 `POST /api/books/{id}/borrow` |
| `优先级` | 是 | P0 / P1 / P2 / P3 |
| `用例类型` | 是 | 正常流程 / 异常流程 / 边界值 / 权限 / 并发 / 幂等 / 性能 |
| `前置条件` | 是 | 数据与状态准备，必要时给出 SQL 或造数步骤 |
| `请求参数` | 是 | path / query / header / body 的关键字段与取值 |
| `测试步骤` | 是 | 编号步骤，1..n |
| `预期结果` | 是 | 状态码 + 业务码 + 数据状态变化，必须可判定 |
| `备注` | 否 | 风险点、依赖、自动化建议 |

## 2. 推荐输出模板（Markdown 表格）

生成用例时，先给「接口分析」，再按「用例类型」分组输出表格：

```markdown
### 接口分析
- 接口：POST /api/books/{id}/borrow
- 功能：读者借阅指定图书
- 关键字段：bookId(路径)、readerId(body,必填)、borrowDays(body,1-90)
- 业务约束：可借册数 > 0；读者无超期未还；单读者最多 5 本
- 风险点：并发借阅导致超借；重复提交产生多条借阅记录；无权限读者借阅

### 正常流程
| 用例ID | 用例标题 | 接口 | 优先级 | 用例类型 | 前置条件 | 请求参数 | 测试步骤 | 预期结果 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| TC-BOOK-001 | 读者借阅在馆图书成功 | POST /api/books/{id}/borrow | P0 | 正常流程 | 图书在馆且可借；读者状态正常且未达借阅上限 | bookId=B001; readerId=R001; borrowDays=30 | 1. 调用接口 2. 查询借阅记录 3. 查询图书库存 | HTTP 200；code=0；生成借阅单；图书可借册数 -1 | 主流程 |

### 异常流程
（同上表格）

### 边界值
（同上表格）
```

## 3. 分组输出顺序（固定）

1. `接口分析`
2. `正常流程`
3. `异常流程`
4. `边界值`
5. `权限与安全`
6. `并发与幂等`
7. `测试数据准备`（YAML/JSON 片段，供阶段二直接使用）
8. `风险与建议`

## 4. 阶段二消费用的机器可读片段

在 `测试数据准备` 章节输出如下 JSON，键名固定：

```json
{
  "domain": "library",
  "cases": [
    {
      "case_id": "TC-BOOK-001",
      "title": "读者借阅在馆图书成功",
      "method": "POST",
      "path": "/api/books/{id}/borrow",
      "priority": "P0",
      "type": "正常流程",
      "headers": {"Content-Type": "application/json", "Authorization": "Bearer ${TOKEN}"},
      "path_params": {"id": "B001"},
      "query": {},
      "body": {"readerId": "R001", "borrowDays": 30},
      "expect": {"status": 200, "code": 0, "assert": ["data.loanId 非空", "库存可借册数=4"]}
    }
  ]
}
```

## 5. 质量红线（AI 自检清单）

生成完成后逐条自检，不满足则重写：

- [ ] 每个接口至少有 1 条正常流程用例；
- [ ] 每个有范围/长度的字段至少覆盖 2 个边界值；
- [ ] 至少包含参数缺失、类型错误、越权、资源不存在四类异常；
- [ ] 预期结果含明确状态码或业务错误码，无「正常返回」式描述；
- [ ] 涉及资源扣减的接口必须有用例覆盖「失败后数据回滚」；
- [ ] 涉及写入的接口必须有用例覆盖「重复提交（幂等）」；
- [ ] 用例ID唯一且连续，无重复；
- [ ] 表格列数一致、Markdown 可正常渲染。
