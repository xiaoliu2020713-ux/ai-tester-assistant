## 7. 跨模块一致性场景（高价值）

1. **容量一致性**：已选人数 = 有效选课记录数；退课后立即一致；不存在「人数 61 / 容量 60」。
2. **学分一致性**：学生已选学分 = Σ(已选课程学分)，退课后同步减少。
3. **课表一致性**：同一学生课表中任意两门课时间不重叠（含候补转正后的情况）。
4. **候补闭环**：退课 → 递补 → 候补位次前移 → 通知，全链路可追踪。
5. **成绩与退课联动**：成绩录入后所有退课入口（学生端/管理端）都必须被拒绝。

## 8. 选课域专属风险点

- **超选**：并发抢课出现已选人数 > 容量，或 Redis 计数与 DB 不一致；
- **重复选课**：网络重试产生多条记录，导致学分重复累计；
- **时间冲突误判**：相邻课时（第 2 节结束 = 第 3 节开始）被错误判定为冲突，或单双周课程未区分；
- **窗口时间**：时区/服务器时间与教务时间不一致导致窗口判定错误；
- **候补顺序**：并发入队导致位次错乱或丢单。
