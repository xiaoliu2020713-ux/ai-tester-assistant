# 电商平台 - 常见测试场景

> 与 `01_business_rules.md` 的 EC 编号对应。优先覆盖资金、库存、幂等三类高风险场景。

## 1. 下单接口（POST /api/orders）

| 场景 | 类型 | 关注点 | 关联规则 |
| --- | --- | --- | --- |
| 单 SKU 正常下单 | 正常流程 | 订单创建、库存锁定、金额正确 | EC-11/EC-12 |
| 多 SKU 混合下单（50 行边界） | 边界值 | 50 行成功、51 行失败 | EC-18 |
| 金额为 0（全额优惠） | 边界值 | 应付 0 元订单可创建，支付方式为「无需支付」 | EC-13 |
| 优惠大于订单金额 | 边界值 | 应付按 0 处理，不产生负数 | EC-13 |
| 数量 0 / 1 / 200 / 201 | 边界值 | 0 与 201 失败 | EC-04 |
| SKU 已下架 | 异常流程 | `SKU_OFF_SHELF` | EC-01 |
| 库存不足（请求量 = 库存 + 1） | 边界值 | 失败，不锁库存 | EC-02 |
| 库存恰好等于请求量 | 边界值 | 成功，可售库存 = 0 | EC-02 |
| 收货地址属于他人 | 权限 | 403 | EC-17 |
| 重复提交（同 Idempotency-Key） | 幂等 | 只创建 1 单，返回同一 orderId | EC-14 |
| 不同幂等键但内容相同 | 正常流程 | 允许创建 2 单（业务允许时） | EC-14 |
| 并发下单最后 1 件库存 | 并发 | 成功数 = 1，无超卖 | EC-03 |
| 未登录下单 | 权限 | 401 | EC-36 |
| 必填字段缺失 / 类型错误 / 非法 JSON | 异常流程 | 400，不抛 500 | 通用基线 |

## 7. 跨模块一致性场景（高价值）

1. **库存三方一致**：下单后「可售库存 = 实物 - 锁定」；支付后「锁定 → 实扣」；取消后库存回滚。
2. **金额一致性**：订单金额 = Σ明细；应付 = 订单 - 优惠 + 运费；支付金额 = 应付；退款 ≤ 明细实付。
3. **状态一致性**：支付成功后立即查询订单必须为「已支付」，不允许长时间停留「待支付」。
4. **幂等闭环**：下单幂等键、支付回调幂等、取消幂等、退款幂等 四处必须全覆盖。
5. **优惠分摊**：多明细使用满减券时，分摊金额之和 = 优惠总额，且每行 ≥ 0。

## 8. 电商域专属风险点

- **超卖**：并发扣库存出现负库存或锁定库存与实物库存不一致；
- **重复支付/重复退款**：回调未幂等导致资金损失；
- **金额精度**：浮点计算导致 0.01 元误差累积；
- **优惠叠加**：多券叠加绕过门槛，出现负金额或 0 元购异常；
- **时序**：支付回调早于订单落库、回调与超时关闭竞态；
- **缓存**：商品下架后缓存未刷新仍可下单。
